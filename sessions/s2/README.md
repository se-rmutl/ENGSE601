# ครั้งที่ 2 ออกแบบกรณีทดสอบ

**วันที่:** พุธ 30 ก.ย. 2569 · **กรณีศึกษา:** Case X Mini (feature ส่งคำขอ)  
**คำถามหลัก:** ทดสอบด้วยค่าอะไร และต้องเห็นอะไร

## เป้าหมาย

ทดสอบทุกค่าไม่ได้ ครั้งนี้เลือกค่าจำนวนน้อยที่จับข้อผิดพลาดได้มากที่สุด

หลังเรียนต้องทำได้:

1. แบ่งกลุ่มข้อมูลตามสิ่งที่ระบบทำ และหาค่าขอบ
2. สร้างตารางตัดสินใจเมื่อผลขึ้นกับหลายเงื่อนไข
3. เขียนกรณีทดสอบเชิงตรรกะ สอบกลับ และทบทวนก่อนส่งต่อ

## แนวคิดสำคัญ

- **การแบ่งกลุ่มข้อมูล (EP)** ค่าที่ระบบทำเหมือนกันอยู่กลุ่มเดียวกัน ใช้ตัวแทนกลุ่มละ 1 ค่า
- **ค่าขอบ (BVA)** ทดสอบค่าที่ขอบของแต่ละกลุ่ม
- **ตารางตัดสินใจ** ใช้เมื่อผลขึ้นกับหลายเงื่อนไข ทุกคอลัมน์ต้องมีกรณีทดสอบ หรือบอกว่าเป็นไปไม่ได้
- **กรณีทดสอบเชิงตรรกะ** อ้างความต้องการ · เงื่อนไขก่อน · ข้อมูลที่ป้อน · ผลที่คาดหวังที่มองเห็นได้
- **ผลที่คาดหวังมาจากกฎ** ไม่ใช่จากพฤติกรรมของแอป และยังไม่มีผลจริงในครั้งนี้
- **ทบทวนชุดกรณีทดสอบ** ใช้คำว่า สอดคล้อง/ไม่สอดคล้อง (ไม่ใช่ Pass/Fail) และผู้ทบทวนไม่ใช่ผู้เขียน
