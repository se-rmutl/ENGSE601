# ครั้งที่ 3 ลงมือทดสอบ

**วันที่:** พุธ 14 ต.ค. 2569 (ครั้งสุดท้ายที่สอน) · **กรณีศึกษา:** แอปสาธิต Case X Mini รุ่น v0.9  
**คำถามหลัก:** รันที่ระดับไหน อย่างไร และผลออกมาเป็นอะไร

## เป้าหมาย

นำชุดกรณีทดสอบจากครั้งที่ 2 ไปรันกับแอปจริงทีละระดับ แล้วบันทึกผลตามจริง

หลังเรียนต้องทำได้:

1. เลือกระดับการทดสอบจากตำแหน่งของพฤติกรรม
2. อ่านและรันการทดสอบระดับ Unit, API และ System
3. เขียน UAT และ NFR ที่วัดได้ และบันทึกผลด้วยสถานะสี่แบบ

## แนวคิดสำคัญ

| ระดับ | ทดสอบอะไร | สภาพแวดล้อม (ตัวอย่างในแอปสาธิต) |
|---|---|---|
| **Unit** | ตรรกะในฟังก์ชันหรือบริการเดียว | เครื่องนักพัฒนาหรือ CI · Jest · ไม่ต้องมีเครือข่ายหรือฐานข้อมูลจริง |
| **Integration / API** | รอยต่อระหว่างส่วนประกอบ เช่น เรียกผ่าน HTTP ถึงชั้นข้อมูล | CI หรือสภาพแวดล้อมทดสอบ · Supertest · ข้อมูลทดสอบที่รีเซ็ตได้ |
| **System** | ทั้งระบบตั้งแต่ต้นจนจบผ่านหน้าจอ | สภาพแวดล้อมทดสอบที่ประกอบครบ · Playwright · เบราว์เซอร์ |
| **UAT** | ผู้ใช้จริงใช้ทำงานจริงได้หรือไม่ และเป็นผู้ตัดสิน | สภาพแวดล้อมใกล้ของจริง · ผู้ใช้จริงหรือตัวแทน |

- เลือกระดับต่ำสุดที่จับพฤติกรรมได้ก่อน แล้วยืนยันเส้นทางสำคัญที่ระดับบน (พีระมิดการทดสอบ)
- **ตัวจำลอง (mock)** ใช้แทนบริการที่ยังไม่มี เช่น อีเมล ทดสอบได้ว่าระบบ “สั่ง” ถูก แต่ไม่ได้พิสูจน์ว่าส่งถึงจริง
- **NFR ต้องวัดได้** มีตัวเลขเกณฑ์ และบันทึกสภาพแวดล้อมที่วัด
- **สถานะ 4 แบบ** `Pass` · `Fail` · `Blocked` (รันไม่ได้เพราะสิ่งภายนอก) · `Not Executed` (ยังไม่ได้รัน)
- **ไม่แต่งผล** ห้ามแก้ผลที่คาดหวังให้ตรงผลจริง และห้ามละข้อที่ไม่ผ่าน · ผลต้องบอกรุ่นและสภาพแวดล้อม
