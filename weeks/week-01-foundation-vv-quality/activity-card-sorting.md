# Activity — Error / Defect / Failure Card Sorting

## คำสั่ง

1. อ่านแต่ละสถานการณ์
2. ถกเถียงภายในทีมว่าควรจัดเป็น Error, Defect, Failure หรือเกี่ยวข้องมากกว่าหนึ่งระดับ
3. ระบุเหตุผลและผลกระทบ
4. นำไปอภิปรายร่วมชั้นเรียน

## สถานการณ์ตัวอย่าง

| สถานการณ์ | การจัดประเภท | เหตุผล |
|---|---|---|
| นักพัฒนาเข้าใจว่า “ส่วนลด 10%” ใช้ได้กับสินค้าทุกรายการ ทั้งที่ requirement ระบุเฉพาะหมวด A | | |
| ฟังก์ชันคำนวณส่วนลดใช้ `subtotal` ก่อนหักสินค้าที่ไม่ร่วมรายการ | | |
| ผู้ใช้ถูกคิดเงินเต็มจำนวนหลังใช้คูปองที่ถูกต้อง | | |
| ผู้ทดสอบพบว่าเลขโทรศัพท์ 9 หลักผ่านการบันทึกได้ | | |
| ระบบส่งอีเมลยืนยันซ้ำ 2 ครั้งเมื่อผู้ใช้กดปุ่มยืนยันเพียงครั้งเดียว | | |
