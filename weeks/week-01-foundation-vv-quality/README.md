# สัปดาห์ที่ 1 — พื้นฐาน V&V และคุณภาพซอฟต์แวร์

**หน่วยเรียน:** หน่วยที่ 1 พื้นฐานการตรวจสอบความสมเหตุสมผลและการทวนสอบซอฟต์แวร์  
**บทเรียน:** 1.1 พื้นฐาน V&V และคุณภาพซอฟต์แวร์  
**เวลา:** 3 ชั่วโมง (ทฤษฎี 3 ชั่วโมง / ภาคปฏิบัติ 0 ชั่วโมง)

## ผลลัพธ์การเรียนรู้ประจำสัปดาห์

หลังเรียน นักศึกษาสามารถ:

1. อธิบายความสัมพันธ์ของ **software quality, QA/QC, testing, verification และ validation** ได้
2. จำแนก **error, defect และ failure** พร้อมอธิบายผลกระทบต่อผู้ใช้และผู้มีส่วนได้ส่วนเสียได้
3. วิเคราะห์กรณีศึกษาด้านคุณภาพ เพื่อระบุว่าอะไรควรถูกตรวจสอบและหลักฐานใดที่ควรมีได้

> เชื่อม CLO1 และปูพื้นฐานสำหรับ CLO2–CLO6 ในสัปดาห์ถัดไป

## เตรียมตัวก่อนเรียน

- เปิดอ่าน `resources.md` เมื่อผู้สอนเพิ่มสื่อแล้ว

## ขั้นตอน Workshop: Quality & V&V Concept Map

1. **เลือกกรณีศึกษา**: ใช้ระบบใกล้ตัวหรือส่วนหนึ่งของโครงงาน ENGSE212 เช่น ระบบสั่งซื้อ ระบบจอง ระบบติดตามงาน หรือระบบจัดการข้อมูล
2. **ระบุเหตุการณ์**: เขียนเหตุการณ์ 3–5 เหตุการณ์ที่อาจทำให้ผู้ใช้ได้รับผลกระทบ
3. **จำแนกเหตุการณ์**: ตัดสินว่าเหตุการณ์ใดเป็น error ของมนุษย์, defect ในชิ้นงาน หรือ failure ที่ผู้ใช้พบ
4. **เชื่อมคำสำคัญ**: วาดแผนผังเชื่อม Software Quality → Testing → Verification → Validation → Stakeholder
5. **กำหนดหลักฐาน**: ระบุว่าในอนาคตจะใช้เอกสารหรือผลใดเป็นหลักฐาน เช่น requirement, test case, screenshot, log, defect report
6. **ใช้ AI ได้อย่างมีเงื่อนไข**: ใช้ AI เพื่อช่วยตั้งคำถามหรือเสนอคำจำกัดความได้ แต่ต้องตรวจเทียบกับแหล่งเรียนรู้และระบุใน AI Use Declaration หากใช้
7. **ส่งงาน**: สร้างไฟล์จาก template `templates/quality-vv-concept-map.md` ใน repository กลุ่มตามคำแนะนำท้ายหน้านี้

## กรณีศึกษาเริ่มต้น

**ระบบคำนวณส่วนลดในร้านค้าออนไลน์**

ผู้ใช้กรอกคูปองส่วนลด 10% ในคำสั่งซื้อราคา 1,000 บาท แต่ระบบแสดงยอดชำระ 1,000 บาทเท่าเดิมและตัดเงินเต็มจำนวน

ให้ทีมอภิปราย:

- Error ของมนุษย์อาจเกิดที่ใด?
- Defect ใน requirement / design / code อาจเป็นอย่างไร?
- Failure ที่ผู้ใช้พบคืออะไร?
- ใครเป็นผู้ได้รับผลกระทบ?
- อะไรควรถูกตรวจสอบก่อนส่งมอบ?
- หลักฐานใดจะช่วยยืนยันว่าปัญหาได้รับการแก้ไขแล้ว?

| เกณฑ์ | 0 | 1 | 2 |
